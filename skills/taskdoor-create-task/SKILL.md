# 创建任务

将用户的自然语言需求转为可执行、可验收的任务，通过已连接的 TaskDoor MCP 创建并回读。这是用于生产环境真实创建任务的 Skill。连接、凭据和工作区由运行环境配置，Skill 不保存固定团队或登录信息。

先按下面的规则判断需求。涉及自主拆分、选择人选、补全基础信息或估算时，读 [任务规划方法与示例](references/task-planning.md)。准备写入时读 [创建流程](references/real-creation.md)；参数不确定时查 [MCP 字段与回执](references/mcp-tools.md) 和当前工具定义。

## 识别意图与准备信息

用户明确要求创建且信息充分时直接执行；只要求规划时先给方案。查询不误建，要求创建不能只查询后结束。若请求指向已有任务的修改，先定位真实对象，只修改授权字段；不能用旧任务冒充本次新建结果。

从原话提取交付物、对象与受众、数量、质量要求、范围限制、人员选择、截止日期和已有资料，保留用户明确值。区分用户要求、资料事实和补充建议；不能把推测的预算、尺寸、业务承诺或审核人当成已确认条件。写入前至少确定每个节点的名称、目标、完成标准和可分配负责人。一次整理任务清单，不要求用户填接口字段。

## 任务拆分与基础信息

- 名称用于识别；目标说明交付希望改变的结果；完成标准逐条说明可检查的交付要求。每个节点都有目标和标准，操作步骤放执行建议，不用模糊标题替代内容。
- 只有结果能独立交付、独立验收，且需要独立负责、交接或并行时才拆分。同一份脚本的分析、撰写、校对通常保留一项任务；不同物料、渠道或独立版本按交付边界拆分。不要增加用户没有要求的拍摄、投放或额外研究。
- 多项交付共同服务于一个整体目标时，建一个汇总范围的父任务和可独立验收的子任务；用户要求分别创建无关任务时用多个根任务。父任务也要保存目标和完成标准，不能只给子任务写标准。
- 父子关系表示范围包含，不自动产生依赖。只为实际需要的前置结果设置依赖，避免自指、循环和重复边。
- 用户已提供的名称、数量、截止日期、执行建议及投入信息应保留。执行建议按原条目保存，不自行扩写成更多条；额外提醒放结果说明，不混入已指定字段。
- 只保留截止日期，不生成或补问开始日期。相对日期按当前日期和用户时区换算；无法确定日期时再询问。投入估算不等于日历排期。
- 只补问会改变交付边界、负责人、可行性或硬期限的缺口，普通操作细节作为执行建议。

## 按职责分配

先核对真实成员身份与参与资格，再用已确认的职责比较人选。成员角色、任务数量、在线情况、姓名都不能证明能力或忙闲。职责来自用户或调用方的确认资料时保留其来源，不能称为 MCP 已返回的职责。

每项任务一个负责人，按该项交付的核心责任匹配：内容制作、业务口径确认、现场执行或渠道交接、最终核查分别比较确认的职责，不因材料有关联就统一交给制作人。用户点名且成员有效时保留选择。参与者只承担必要且具体的贡献；任务无协作需要就不添加，不能为了“完整”加入所有成员或重复添加负责人。职责不足以判断且用户未指定负责人时，先补齐人选，不能虚构成员或全部默认给当前用户。

## 预计投入

用户已明确给出投入、方法和依据时保留，不用模型估算覆盖。需要估算时，按完成标准列出不重叠的人工工作明细，考虑规模、难度、资料缺口、协作、修改和核验；用同一单位的 O≤M≤P 三点估算，按 (O+4M+P)/6 汇总，并说明工作方法与假设。等待和无人值守运行不计入；未知估算省略，不能填零。1 人时=60 分钟，1 人天=480 分钟；父任务不重复计叶子工时。

## 交付结果

只在开始时整理一次任务树与字段清单，取得工具回执后执行剩余动作，不反复重写方案。完成后简要展示真实任务 ID、名称、负责人、层级及保存的基础信息；不重复展开估算过程和长篇拆分论证。调用方要求 JSON 时，将已回读字段组织为任务对象，用 `children` 展示层级；不能将 `children` 发送给创建工具。未设置的字段不补造。

JSON 结果中的任务应包含实际 ID、名称、目标、负责人 ID、完成标准及已保存的可选字段；层级来自真实 `parentTaskId`，人员名称来自已核对成员资料。任务状态和归属状态按回读值呈现，不把已创建说成已完成或已接受。调用方已经汇总真实字段且只要结论时，遵守其返回格式，不再复制整棵任务树。

有部分失败时，报告具体原因、已成功的任务 ID 和未完成动作。工具未连接或权限不足时说明缺口，可以准备未执行方案，不能声称任务已创建。
